# ランレングス圧縮シミュレータ

## 概要

情報Ⅰ「情報のデジタル表現」第6回の授業用シミュレータ．実教出版『最新情報Ⅰ』例題13・確認問題10の約束に従う．

- 1行ごとに圧縮する
- 最初の1ビットは色（A=0／B=1）
- 次の4ビットは「連続する個数−1」

公開URL: 未公開

## できること

- 16×16 の盤面をタップ・ドラッグで塗る（A＝淡色／B＝濃色．最初に触れたマスの反転値でなぞり全体を塗る）
- 行ごとに，元の16ビット・圧縮後のビット列（最初の1ビットと各ランの4ビットを `0 | 1111` のように区切って表示）・「16ビット→nビット」を表示．n が16より大きい行は朱色で「増えた」と注記する（縮んだ行はうっすら緑）
- 合計欄：圧縮前256ビット／圧縮後／圧縮率（圧縮後÷圧縮前×100．小数第3位までで割り切れる値はそのまま，第4位以下まで出る値は小数第3位までに丸めて「≒」．例：84ビット→32.8125 ％→≒ 32.813 ％）／増えた行の数
- 見本ボタン：例題13の図・確認問題10の図・市松模様・横じま・全部A・全部消す．選んでいる見本は濃い緑の太字で示す（`aria-pressed`）．盤面を手で塗って見本と一致しなくなったら解除．「全部A」「全部消す」は同じ盤面なので押した方を示す（読み込み直後は盤面が全部Aなので「全部消す」が押された状態）
- 行表示の上に常に見える注記：「4ビットで表せるのは 0〜15．だから『個数−1』で書く（16個連続は 15＝1111）」（`?hide=1` でも表示．数字の答え・「圧縮率」の語は含まない）
- 「圧縮の約束」の折りたたみ（最初の1ビット・個数−1を4ビットで書く・17個以上は起きない．0〜15の理由は上の注記に一本化）

## 授業で使うときのURL

- 通常: `index.html`
- 導入用: `index.html?hide=1`（数字と「圧縮率」の語を隠す）

## しくみ

- 単一の `index.html`．外部ライブラリなし
- https 前提で配信する
- pointer イベントを使い，タッチ操作に対応する
